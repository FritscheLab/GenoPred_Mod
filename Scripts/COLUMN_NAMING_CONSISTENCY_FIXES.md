# Column Naming Consistency Fixes for Raw Profile Files

## Problem Identified

The raw profile files generated by `ref_scoring_raw.R` and `target_scoring_pipeline_raw.R` had inconsistent column naming schemes and non-deterministic column ordering, which could cause issues when comparing or merging results.

## Issues Fixed

### 1. Inconsistent Column Naming
**Before:**
- Reference scoring: Used `"SCORE_"` prefix for all columns
- Target scoring: Used `"{name}_"` prefix (e.g., `"height_"`, `"bmi_"`)

**After:**
- Both scripts now use: `"{method}_{name}_{score_column}"` format
- Example: `"GWAS_height_SCORE1"`, `"GWAS_bmi_SCORE1"`

### 2. Non-deterministic Column Order
**Before:**
- Used `set.seed(1)` followed by `sample(tmp_score_files)` for batching
- This could potentially lead to different column orders across runs

**After:**
- Removed random sampling
- Uses deterministic ordering: `split(tmp_score_files, rep(1:num_batches, ...))`

### 3. Score File Processing Order
**Before:**
- Score files processed in whatever order returned by `list_score_files()`

**After:**
- Score files sorted by `method` then `name`: `score_files[order(score_files$method, score_files$name), ]`
- Applied both initially and after timestamp filtering

## Benefits

1. **Consistency**: Same score file will have identical column names in both reference and target profile files
2. **Predictability**: Column order is deterministic and reproducible across runs
3. **Clarity**: Column names now include method information, making it easier to identify the source
4. **Compatibility**: Results from different runs can be reliably compared and merged

## Example Column Names

**Before (inconsistent):**
- Reference file: `FID`, `IID`, `SCORE1`, `SCORE2`, `SCORE3`
- Target file: `FID`, `IID`, `height_SCORE1`, `height_SCORE2`, `height_SCORE3`

**After (consistent):**
- Reference file: `FID`, `IID`, `GWAS_height_SCORE1`, `GWAS_height_SCORE2`, `GWAS_height_SCORE3`
- Target file: `FID`, `IID`, `GWAS_height_SCORE1`, `GWAS_height_SCORE2`, `GWAS_height_SCORE3`

## Files Modified

1. `/Scripts/ref_scoring/ref_scoring_raw.R`
2. `/Scripts/target_scoring/target_scoring_pipeline_raw.R`

## Backward Compatibility

These changes affect the output format. If you have existing workflows that depend on the old column naming scheme, you may need to update them to use the new `{method}_{name}_` prefix format.
